\section{Informe de guía práctica}

\subsection{Objetivos}

\subsubsection{General}

Implementar y verificar el protocolo de enrutamiento dinámico OSPF en una topología de seis routers en Cisco Packet Tracer, manteniendo el direccionamiento y la estructura física utilizada en la práctica anterior con RIP.

\subsubsection{Específicos}

\begin{itemize}
    \item Eliminar la configuración de RIP en los routers de la topología y reemplazarla por OSPFv2 para IPv4.
    \item Configurar Router ID únicos y anunciar las redes directamente conectadas en el área 0 de OSPF.
    \item Verificar la formación de vecinos OSPF, las rutas aprendidas y la conectividad entre las redes LAN.
\end{itemize}

\subsection{Modalidad}

La práctica se desarrolló en modalidad experimental mediante simulación en Cisco Packet Tracer. Se trabajó sobre una topología previamente funcional con RIP/RIPng, manteniendo los mismos routers, enlaces, interfaces y direcciones IP.

\subsection{Tiempo de duración}

\textbf{Presencial:} Según lo establecido en la guía práctica proporcionada por el docente.\\
\textbf{No presencial:} Tiempo adicional destinado a configuración, verificación, corrección de errores y elaboración del informe.

\subsection{Instrucciones}

Se debe realizar el reto de migrar la práctica anterior desde RIP hacia OSPF, sin modificar la topología física. Para ello, se deben eliminar las configuraciones previas de RIP, activar OSPF en los routers correspondientes, anunciar las redes conectadas y verificar la conectividad mediante comandos de diagnóstico.

\subsection{Experiencia concreta: ¿Qué se hizo?}

En esta fase se realizó la configuración de OSPF en la topología. Se mantuvo la estructura de red usada anteriormente y se activó el proceso OSPF 1 en todos los routers. Cada router recibió un Router ID único y se anunciaron las redes conectadas en el área 0.

R1 participa en tres redes OSPF: el enlace con R5, el enlace con R3 y el enlace con R4.

router-id 1.1.1.1
network 10.0.7.0 0.0.0.3 area 0

network 10.0.2.0 0.0.0.3 area 0

write memory

\subsection{Conceptualización abstracta: ¿Qué se aprendió?}

OSPF es un protocolo de enrutamiento dinámico de estado de enlace. A diferencia de RIP, que trabaja con saltos como métrica principal, OSPF utiliza el costo de los enlaces para seleccionar la mejor ruta. En esta práctica se utilizó OSPF en área única 0, lo cual permitió que todos los routers compartieran información de enrutamiento dentro de la misma área.

\subsubsection{Conceptos principales de OSPF}

\begin{table}[H]
\centering
\small
\begin{tabularx}{\textwidth}{|L{4cm}|Y|}
\hline
\textbf{Concepto} & \textbf{Definición} \\ \hline
OSPF & Protocolo de enrutamiento dinámico de estado de enlace que calcula la mejor ruta usando el algoritmo SPF. \\ \hline
Router ID & Identificador único del router dentro del dominio OSPF. En la práctica se usaron valores como 1.1.1.1, 2.2.2.2 y 3.3.3.3. \\ \hline
Área OSPF & División lógica de la red. En esta práctica todos los routers se configuraron en el área 0. \\ \hline
Vecindad OSPF & Relación que se forma entre routers conectados directamente para intercambiar información de enrutamiento. \\ \hline
Estado FULL & Estado que indica que los routers vecinos completaron el intercambio de información OSPF. \\ \hline
Ruta OSPF & Ruta aprendida dinámicamente por OSPF. En la tabla de enrutamiento aparece identificada con la letra O. \\ \hline

\subsection{Experimentación activa: ¿Qué se podría mejorar?}

Como mejora, se podría modificar el costo de algunos enlaces para observar cómo cambia la ruta seleccionada por OSPF. Por ejemplo, se puede asignar un costo manual a un enlace serial para obligar al protocolo a seleccionar una ruta alternativa.

\begin{lstlisting}
interface serial0/1/0
ip ospf cost 500
\end{lstlisting}

También se podría apagar temporalmente un enlace para comprobar la convergencia de OSPF y verificar si la red utiliza una ruta redundante.

\begin{lstlisting}
interface serial0/0/0
shutdown
\end{lstlisting}

Después de realizar el cambio, se pueden usar los siguientes comandos:

\begin{lstlisting}
show ip ospf neighbor
show ip route ospf
ping 195.0.50.10
\end{lstlisting}

El resultado esperado es que OSPF actualice su tabla de enrutamiento y seleccione una ruta alternativa si existe conectividad por otro camino.

\section{Problemas encontrados y soluciones}

\subsection{Error de configuración en R3}

En R3 se ingresaron inicialmente redes que pertenecían a R2. Esto provocaba que OSPF no representara correctamente las redes conectadas al router. Para corregir el problema, se eliminó el proceso OSPF y se configuró nuevamente.

\begin{lstlisting}
no router ospf 1
router ospf 1
router-id 3.3.3.3
network 195.0.30.0 0.0.0.255 area 0
network 10.0.1.0 0.0.0.3 area 0
network 10.0.5.0 0.0.0.3 area 0
\end{lstlisting}

\subsection{Reinicio del proceso OSPF}

Después de corregir la configuración, se reinició el proceso OSPF.

\begin{lstlisting}
clear ip ospf process
\end{lstlisting}

El reinicio provocó que las vecindades bajaran temporalmente, pero después volvieron a establecerse correctamente.

\subsection{Estado EXSTART en R6}

En R6 se observó temporalmente el estado \texttt{EXSTART} con R2. Este estado forma parte del proceso de negociación OSPF. Después de completar la sincronización, la vecindad cambió a \texttt{FULL}.

\subsection{Reflexión ética y académica}

La IA puede utilizarse como apoyo para comprender comandos, organizar información y redactar informes, pero no debe reemplazar la práctica directa en Packet Tracer. En redes es necesario ejecutar, observar, verificar y corregir los errores dentro del simulador. Copiar comandos sin analizarlos puede causar configuraciones incorrectas, especialmente cuando las interfaces o direcciones IP no coinciden con la topología real.

\section{Conclusiones}

Se realizó la migración de la topología desde RIP hacia OSPF, manteniendo las mismas redes, enlaces e interfaces de la práctica anterior. La configuración se aplicó mediante el proceso OSPF 1 y área 0, asignando Router ID únicos a cada router.

La verificación permitió comprobar que OSPF aprendió rutas dinámicamente y que los vecinos alcanzaron el estado \texttt{FULL}. En R3 se observaron rutas OSPF marcadas con la letra \texttt{O}, lo que confirmó que el protocolo estaba funcionando correctamente.

Durante la práctica se corrigió un error de configuración en R3, donde inicialmente se anunciaron redes que no correspondían al router. Esta corrección permitió comprender la importancia de verificar las redes conectadas antes de anunciar rutas en OSPF.

\section{Recomendaciones}

Se recomienda verificar el direccionamiento de cada interfaz antes de configurar OSPF, para evitar anunciar redes incorrectas. También se recomienda utilizar comandos como \texttt{show ip protocols}, \texttt{show ip ospf neighbor} y \texttt{show ip route ospf} después de cada configuración.

Además, se recomienda tomar capturas de pantalla de la topología, la configuración de cada router, las tablas de enrutamiento, los vecinos OSPF y las pruebas de conectividad, ya que estas evidencias respaldan el informe técnico.
