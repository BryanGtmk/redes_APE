\section{Informe de guía práctica}

\subsection{Objetivos}

\subsubsection{General}

Configurar y verificar rutas estáticas IPv4 e IPv6 en una topología de red empresarial simulada en Cisco Packet Tracer, con el propósito de comprender el funcionamiento del enrutamiento manual, la comunicación entre redes remotas y la validación de conectividad mediante comandos de diagnóstico.

\subsubsection{Específicos}

\begin{itemize}
    \item Configurar direcciones IPv4 e IPv6 en routers y equipos finales de acuerdo con el direccionamiento asignado al Grupo 8.
    \item Implementar rutas estáticas IPv4 e IPv6 para permitir la comunicación entre las cuatro redes LAN.
    \item Verificar la conectividad mediante comandos como \texttt{ping}, \texttt{tracert}, \texttt{show ip route} y \texttt{show ipv6 route}.
\end{itemize}

\subsection{Modalidad}

La práctica se desarrolló de forma experimental mediante el simulador Cisco Packet Tracer. Se configuró una topología de red con routers, switches y PCs, aplicando direccionamiento IPv4 e IPv6, rutas estáticas y pruebas de conectividad entre diferentes redes LAN.

\subsection{Actividades por desarrollar}

Para el desarrollo de la práctica se realizaron las siguientes actividades:

\begin{enumerate}
    \item Se creó una topología en Cisco Packet Tracer con cuatro routers, cuatro switches y ocho PCs.
    \item Se conectaron las PCs a los switches mediante cable de cobre directo.
    \item Se conectaron los switches a los routers mediante interfaces GigabitEthernet.
    \item Se conectaron los routers entre sí mediante enlaces seriales.
    \item Se configuraron direcciones IPv4 e IPv6 en las interfaces LAN y WAN de cada router.
    \item Se configuraron direcciones IPv4 e IPv6 en los equipos finales.
    \item Se habilitó el enrutamiento IPv6 mediante el comando \texttt{ipv6 unicast-routing}.
    \item Se configuraron rutas estáticas IPv4 e IPv6 en cada router.
    \item Se verificó el estado de las interfaces y las tablas de enrutamiento.
    \item Se realizaron pruebas de conectividad con \texttt{ping} y \texttt{tracert}.
\end{enumerate}

\subsection{Análisis de resultados}

Los resultados obtenidos evidencian que el enrutamiento estático fue configurado correctamente, ya que las PCs de diferentes redes LAN lograron comunicarse entre sí tanto en IPv4 como en IPv6.

En IPv4, los paquetes enviados desde PC1 hacia las redes 192.168.82.0/24, 192.168.83.0/24 y 192.168.84.0/24 fueron respondidos correctamente. Esto demuestra que los routers conocen las redes remotas mediante rutas estáticas.

En IPv6, también se verificó la conectividad hacia las redes 2001:DB8:8:2::/64, 2001:DB8:8:3::/64 y 2001:DB8:8:4::/64. Para esto fue necesario habilitar el enrutamiento IPv6 en los routers mediante el comando \texttt{ipv6 unicast-routing}.

Las tablas de enrutamiento permitieron comprobar la presencia de rutas estáticas, identificadas con la letra \texttt{S}. Estas rutas indican que el router conoce una red remota porque fue configurada manualmente por el administrador de red.

También se comprobó que, si una dirección IP está mal escrita en una PC, la comunicación puede fallar aunque las rutas estén correctamente configuradas. Por esta razón, es importante verificar la dirección IP, máscara, gateway y prefijo IPv6 de cada equipo final.

\subsection{Conclusiones}

Se configuró correctamente una topología de red compuesta por cuatro routers, cuatro switches y ocho PCs, aplicando direccionamiento IPv4 e IPv6 correspondiente al Grupo 8.

El enrutamiento estático permitió la comunicación entre redes LAN remotas sin utilizar protocolos de enrutamiento dinámico. Para ello, fue necesario configurar manualmente las rutas hacia cada red no conectada directamente.

La verificación mediante \texttt{ping}, \texttt{tracert}, \texttt{show ip route} y \texttt{show ipv6 route} confirmó que los routers reenviaban correctamente los paquetes entre las distintas LAN.

IPv6 requiere una configuración adicional en los routers, principalmente la activación del comando \texttt{ipv6 unicast-routing}, ya que sin esta instrucción el router no reenvía paquetes IPv6 entre redes.

%========================================================
\subsection{Recomendaciones}

Se recomienda revisar cuidadosamente el direccionamiento IP de cada PC, debido a que un error en la dirección IPv4, IPv6, gateway o prefijo puede impedir la conectividad.

También se recomienda verificar el estado de las interfaces con \texttt{show ip interface brief} antes de realizar las pruebas de conectividad, ya que las interfaces deben encontrarse en estado \texttt{up/up}.

Finalmente, se recomienda guardar la configuración de cada router con \texttt{write memory} para evitar la pérdida de los cambios realizados durante la práctica.
